---
title: Manage .akr setups
description: Export, import, and maintain Akron setup state.
---

Akron setup state includes the options, bindings, StartPos slots, and tool settings that `.akr` setup packs can carry.

## Start from current settings

Configure Akron directly, then export the current settings as a setup pack once they match the state you want to preserve. Export a scoped pack when you need to share one tool group.

## Maintain setups

<Steps>
  <Step title="Start from a baseline">
    Export a fresh baseline before changing individual tools.
  </Step>
  <Step title="Change one tool group at a time">
    Configure overlay behavior, HUD tools, StartPos tools, visual settings, and interop one group at a time so you can identify configuration issues.
  </Step>
  <Step title="Export a pack">
    Export an `.akr` setup pack when the setup is stable.
  </Step>
  <Step title="Use scoped imports">
    Import only the section you need when applying shared StartPos, Keybinds, Auto Kill, Auto Deafen, Recorder, Audio, or HUD packs.
  </Step>
</Steps>

## Restore a baseline

Import the previously exported scope when a tool group no longer matches your intended baseline. A scoped import restores that group while leaving unrelated settings alone. StartPos imports replace slots for the pack's target map and keep slots for other maps.

## Clean setup hygiene

- Keep state-changing tools out of submitted-run setups.
- Check every suboption.
- Avoid importing whole setup packs from untrusted sources into submitted-run setups.
- Use [Clean vs cheat classifications](/concepts/clean-vs-cheat) when deciding where a setting belongs.
